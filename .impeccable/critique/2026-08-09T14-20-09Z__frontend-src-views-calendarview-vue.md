## Design Specificity Verdict

交易日历在信息架构上明显属于 Lucking：A 股交易状态、个人重要日、数据新鲜度和月度概览被组合在同一研究工作区，冷蓝灰与少量金色也符合“月石鎏金”。但交互层仍像通用 CRUD 日历：缺少研究优先级、单日聚焦、事件上下文和高效率日历导航，因此产品专属性只完成了一半。

## Overall Impression

第一眼是可信、冷静、结构清楚的专业日历；最大的机会不是再加装饰，而是把“月份网格”升级为真正服务投资研究的“交易日程工作台”：重点事件不遗漏、单日内容可聚焦、键盘和移动端都能高效操作。

## What's Working

- 交易日状态与个人重要日分层表达，没有把两类语义混为一谈。
- 视觉系统较自律：主题令牌、亮暗色支持、可见焦点和克制金色总体符合品牌承诺。
- 基础状态完整：加载、错误、空状态、字段校验、重复冲突以及“等待真实数据”都比普通日历更诚实。

## Priority Issues

### [P1] 同一天超过三项的重要日不可发现

**为什么重要**：网格只显示三项，“另有 N 项”是静态文字。研究人员最不能接受的是重要事项存在但不可见，这会直接破坏日历作为复盘与提醒工具的可信度。

**修复**：把“另有 N 项”改为按钮，打开该日抽屉或 Popover，显示全部事件、备注、编辑和删除；关闭后恢复焦点。点击日期应先选中并同步右侧单日议程，明确提供“添加重要日”作为次级动作。

**建议命令**：`$impeccable harden 交易日历`

### [P1] 移动端策略是压缩和横向滚动，不是重组任务

**为什么重要**：当前使用 1100/760px 断点，并保留约 504px 最小日历宽度；窄屏下市场状态文字还会消失。这既偏离项目 860/620px 约束，也让移动端用户难以快速判断交易日与事件。

**修复**：明确实现 860/620 两级布局。620px 以下采用紧凑月历 + 选中日议程，或直接提供按日期排列的月度议程视图；交易状态必须保留文字、图标或纹理，而不是仅靠颜色。

**建议命令**：`$impeccable adapt 交易日历`

### [P1] 日历键盘模型与触控尺寸不合格

**为什么重要**：每个当月日期都是 `tabindex="0"`，没有网格语义或方向键导航，键盘用户要顺序穿过整个月；事件按钮约 27px、删除按钮约 26px，低于项目 40×40px 触控要求。

**修复**：使用 `role="grid"/"gridcell"`、roving tabindex，以及方向键、Home/End、PageUp/PageDown；Enter/Space 执行唯一、可预测的主动作。事件和删除目标扩至至少 40×40px，并在无障碍名称中包含事件标题。

**建议命令**：`$impeccable audit 交易日历`

### [P2] 未知状态与增删反馈不完整

**为什么重要**：“待确认”可能只有辅助技术能读到，视觉上没有稳定标签；删除缺少忙碌态、成功反馈和可执行失败恢复。对数据可信度敏感的投资研究场景，这会制造不确定感。

**修复**：所有当月日期都应有可见的状态文本/图标/纹理；补充保存和删除中的禁用状态、成功 Toast、失败原因与重试。删除改用品牌 Dialog，并避免重复提交。

**建议命令**：`$impeccable harden 交易日历`

## Persona Red Flags

**高频研究用户**：必须 Tab 穿过整个月，不能方向键移动、跳转日期或批量管理密集事件；事件越多，效率下降越明显。

**首次使用者**：不知道 `CN-S` 是什么，“待确认”也没有原因或下一步；“点击日历添加重要日”的说明离实际单元格较远，容易把日期点击误解为查看详情。

**投资者/研究员**：溢出事件脱离日期上下文，数据新鲜度没有说明来源和覆盖范围，也无法区分普通提醒与市场敏感的重要日，难以形成盘前/盘后优先级。

## Minor Observations

- 交易日圆点使用通用绿色 `--lk-success`，与“不使用绿色作为通用状态色”的品牌原则有张力，建议设置独立市场语义令牌。
- 编辑和删除按钮的无障碍名称应包含目标事件标题。
- 日期与计数适合使用 tabular numerals。
- 原生 `confirm` 与 PrimeVue Dialog 的视觉及语言不一致。
- 右侧月度概览在桌面有价值，但窄屏堆叠后可能与日历内容重复。
- 检测器指出的单侧 3px 金色边框可改成更轻的状态点、顶部刻线或背景层级，避免形成模板化“侧标签卡片”。

## Questions to Consider

- 日历的首要任务究竟是“管理提醒”，还是“理解下一交易日前最重要的事项”？
- 点击日期应该立即创建，还是先打开单日研究议程，再由明确按钮创建？
- 右侧概览若改成“即将发生 / 今日 / 已过期”，是否比重复月历顺序更有研究价值？
- “待确认”应提供哪些证据，才能让用户判断应该等待、刷新还是不信任该日期？
