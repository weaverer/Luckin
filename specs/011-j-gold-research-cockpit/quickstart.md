# J金股研究驾驶舱快速验证

## 前置条件

1. 启动项目既有 MySQL、ClickHouse、Redis 和 API/前端服务。
2. 准备已授权测试用户、一个完整推荐月份、上月及 3/8/12 个月历史数据、股票行情、行业分类和沪深 300 基准。
3. 确认服务健康：`curl -fsS http://127.0.0.1:8000/healthz`。

## 自动化检查

```bash
uv run pytest
cd frontend
pnpm lint
pnpm typecheck
pnpm test -- --run
pnpm build
pnpm exec playwright test
```

预期：所有指标与人工核算一致；每个非 204 响应含统一六字段信封；分页仅位于 `data.pagination`；后复权价格、原始成交量/额和 UTC 时间字段口径通过契约测试。

## 手工验收

1. 打开 J金股页面，确认默认最近完整月份、更新时间、数据状态和来源说明。
2. 变更月份、券商和行业，确认指标卡、雷达、异动、行业和趋势同步变化；清除、刷新和模块独立重试有效。
3. 验证同股多券商只显示一个股票结果，但券商数和详情清单正确；打开详情并加入自选，确认无交易行为。
4. 注入上月缺失、基准缺失、行情延迟、上市不足 20/60 个交易日、停牌和部分模块失败，确认显示降级状态而非零值或模拟结论。
5. 在亮暗主题及宽度大于 860px、620—860px、小于 620px 下验证键盘焦点、文本状态、图表替代文本和表格移动端呈现。

## 数据来源与计算链路

- 月份及推荐事实来自既有券商金股同步结果；只有已成功发布的同步月份可作为“完整月份”，推荐身份沿用“推荐月份 + 规范化券商名称 + 股票身份”。
- 股票代码、名称和上市状态来自股票主数据；当前仓库没有可验证的股票行业映射，因此行业筛选与行业共识保留接口能力，并在真实数据中明确降级为“部分覆盖”，不会用模拟分类补齐。
- 股票收益及 60 日新高使用 ClickHouse 日线与复权因子计算的后复权收盘价；成交量和成交额不改口径。沪深 300 使用规范指数代码 `000300.CSI` 的日线收盘价。
- 20 日超额只使用股票与基准共有的 21 个交易日收盘价；券商历史样本从推荐月首后的首个共同交易日起观察。缺少共同窗口时不产生收益值或等级。
- 页面聚合在查询时生成，不新增同步任务或模拟快照；响应和股票详情携带来源、生成时间、统计口径与质量状态。

## 排障

- 首先按 `request_id` 查 API 结构化日志，再按月份、筛选上下文和模块状态定位。
- 若结果为空，区分“无事实数据”和“筛选无结果”；不得通过刷新改变统计月份。
- 若指标为数据不足，检查交易日窗口、行情更新时间、基准覆盖和行业映射状态。
- 若月份自动回退，检查目标月份同步运行是否为 `SUCCEEDED` 且已发布；页面只回退到最近的完整月份。
- 若只有行情相关指标失败，推荐事实、券商计数和可验证历史仍应保留；按模块质量说明判断影响范围后重试。
- 若契约失败，优先检查统一响应信封、HTTP 状态/业务码分离、分页位置和 UTC 时间戳。
