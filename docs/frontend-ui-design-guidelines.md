# Lucking 前端 UI 设计与开发规范

## 1. 文档目的

本文档定义 Lucking 后续前端页面的视觉风格、主题色、布局规则、组件使用方式和验收标准。

所有新增页面和公共组件都应遵守本文档。未经设计评审，不应在单个页面内创建新的颜色体系、间距体系或组件外观。

相关资料：

- [前端技术栈](./frontend-technology-stack.md)
- [交互式视觉 Demo](../design/frontend-theme-demo.html)
- [亮色主题预览](../design/frontend-theme-demo-light.png)
- [暗色主题预览](../design/frontend-theme-demo-dark.png)

视觉 Demo 用于确认设计方向，不作为生产组件代码直接复制。生产实现应使用 Vue 3、PrimeVue 4 Styled Mode 和统一 Design Token。

## 2. 设计定位

### 2.1 主题名称

**月石鎏金（Moonstone & Gilded Light）**

### 2.2 风格定义

整体风格定位为：

> 冷静、精确、轻量的科技工作台。以宝石蓝建立专业与科技感，以月石白提供清晰、耐看的内容空间，以少量明亮香槟金表达幸运、价值和关键时点。

### 2.3 视觉关键词

- 冷静科技
- 月石质感
- 精密数据
- 克制高级
- 明亮鎏金
- 长时间使用友好

### 2.4 核心原则

1. **内容优先**：视觉装饰不能干扰数据、表格、图表和操作。
2. **低疲劳**：大面积使用低饱和月石白和冷蓝灰，不使用纯白或纯黑。
3. **金色克制**：香槟金只用于品牌签名、关键时点和少量强调，面积不超过页面可见区域的 5%。
4. **层级清楚**：主要依靠背景明度、边框和留白区分层级，不依赖重阴影。
5. **一致可学**：相同操作在不同页面中保持相同的位置、颜色、名称和反馈。
6. **无绿色主题**：主题和通用状态不使用绿色，避免破坏已确认的视觉方向。

## 3. 页面整体结构

### 3.1 桌面端布局

```text
┌──────────────────┐  ┌──────────────────────────────────────┐
│                  │  │ 页面上下文                  搜索/工具 │
│ Logo             │  │ 页面主标题                           │
│                  │  │                                      │
│ 当前导航         │  │ 视图切换                  日期/操作   │
│ 其他导航         │  ├──────────────────────────────────────┤
│                  │  │                                      │
│                  │  │              主内容                  │
│                  │  │                                      │
│                  │  ├─────────────────────────┬────────────┤
│ 底部导航         │  │        次要内容         │ 辅助内容   │
│ 用户信息         │  │                         │            │
└──────────────────┘  └─────────────────────────┴────────────┘
```

### 3.2 基础尺寸

| 项目 | 尺寸 |
| --- | ---: |
| 应用外边距 | `20px` |
| 侧边栏宽度 | `248px` |
| 侧边栏圆角 | `24px` |
| 侧边栏内边距 | `18px` |
| 侧边栏与内容间距 | `20px` |
| 导航项高度 | `46px` |
| 页面内容间距 | `16px` 或 `20px` |
| 内容 Surface 圆角 | `16px` |
| 控件高度 | `40px` 或 `44px` |
| 表格建议行高 | `44px` 至 `48px` |

### 3.3 页面标题区

页面标题区不使用贯穿全屏的传统顶栏，应直接属于内容画布。

推荐结构：

```text
辅助上下文                              搜索 / 主题 / 通知
页面主标题

视图切换                              日期范围 / 主要操作
```

规则：

- 页面只能有一个 `h1`。
- 主标题保持简洁，不附加无意义欢迎语。
- 页面主要操作放在右侧，且每个页面最多突出一个。
- 搜索、主题和通知属于全局能力，应保持固定位置。
- 页面筛选和视图切换放在标题区下方，不塞入侧边栏。

### 4.3 通用状态色

主题不使用绿色。状态不能只靠颜色表达，必须同时使用文字或图标。

| 状态 | 亮色文字 | 亮色背景 | 暗色文字 | 暗色背景 |
| --- | --- | --- | --- | --- |
| 成功/完成 | `#4F789D` | `#D8E4EE` | `#84A9C8` | `#31495F` |
| 信息/观察 | `#596F9D` | `#DDE4F1` | `#93ABD1` | `#334764` |
| 警告 | `#9B6F2E` | `#EEE2CA` | `#D7B064` | `#55482F` |
| 错误/危险 | `#AC5367` | `#F0DCE2` | `#DB8293` | `#583845` |

业务数据的涨跌色属于数据语义层，应单独定义，不得直接复用主题主色、香槟金或通用状态色。

### 4.4 香槟金使用规则

香槟金是 Lucking 的品牌签名色，不是普通按钮色。

允许使用：

- Logo 中的小面积标记。
- 当前导航项左侧的细渐变线。
- 图表关键时点、选中游标和特殊标记。
- 需要特别关注的短数字或提示。
- 少量品牌插图细节。

禁止使用：

- 大面积页面背景。
- 所有主要按钮。
- 整行表格背景。
- 大块图表填充。
- 长段正文。
- 普通选中状态。

面积控制：

```text
月石白和冷蓝灰  70%
宝石蓝结构色    25%
明亮香槟金       5% 以内
```

## 5. Design Token 实现

### 5.1 Token 文件

建议结构：

```text
src/styles/
├── theme/
│   ├── preset.ts
│   └── theme-store.ts
├── tokens.css
├── reset.css
└── app.css
```

职责：

- `preset.ts`：PrimeVue Styled Mode Token。
- `tokens.css`：项目布局、图表、品牌金等 PrimeVue 之外的 Token。
- `theme-store.ts`：主题切换、系统偏好和持久化。
- `reset.css`：基础重置。
- `app.css`：应用级布局和通用样式。

### 5.2 项目 CSS Token

建议以 Aura 为基础创建项目 Preset：

```ts

  semantic: {
    primary: {
      50: '#eef3fa',
      100: '#d9e3f2',
      200: '#bccde5',
      300: '#98afd2',
      400: '#718cc0',
      500: '#3f5f9a',
      600: '#324e82',
      700: '#293f6b',
      800: '#253754',
      900: '#25344d',
      950: '#182237',
    },
    colorScheme: {
      light: {
        surface: {
          0: '#f3f6fa',
          50: '#eef2f7',
          100: '#e5ebf3',
          200: '#d7e0ec',
          300: '#bcc8d8',
          400: '#8e9aaf',
          500: '#66748a',
          600: '#526078',
          700: '#3d4b64',
          800: '#303d56',
          900: '#25344d',
          950: '#182237',
        },
      },
      dark: {
        surface: {
          0: '#dee6f1',
          50: '#cdd7e5',
          100: '#b7c3d4',
          200: '#a4b0c4',
          300: '#8c99af',
          400: '#79869e',
          500: '#63718a',
          600: '#526078',
          700: '#35445f',
          800: '#2c3850',
          900: '#232e42',
          950: '#161d2b',
        },
      },
    },

```

应用配置：

```ts
app.use(PrimeVue, {
  theme: {
    preset: LuckingPreset,
    options: {
      darkModeSelector: '.app-dark',
      cssLayer: {
        name: 'primevue',
        order: 'reset, primevue, app',
      },
    },
  },
})
```

### 6.2 覆盖优先级

组件外观调整按以下顺序进行：

```text
Semantic Token
    ↓
Component Token
    ↓
项目级组件封装
    ↓
局部 CSS
```

直接覆盖 PrimeVue `.p-*` 内部类只能作为最后手段，并需要说明原因。

## 7. 字体与数字

### 7.1 字体角色

```css
:root {
  --lk-font-ui:
    Inter,
    "Noto Sans SC",
    "Microsoft YaHei",
    system-ui,
    sans-serif;

  --lk-font-data:
    "IBM Plex Mono",
    "Roboto Mono",
    monospace;
}
```

使用规则：

- 中文界面、标题和正文使用 UI 字体。
- 价格、百分比、时间、编号和统计值使用数据字体或等宽数字特性。
- 不在大段正文中使用等宽字体。
- 无法加载网络字体时必须正常回退到系统字体。

### 7.2 字号层级

| 用途 | 字号 | 字重 |
| --- | ---: | ---: |
| 页面主标题 | `28px` 至 `38px` | `650` 至 `700` |
| 区域标题 | `15px` 至 `16px` | `650` 至 `700` |
| 正文和表格 | `13px` 至 `14px` | `400` 至 `500` |
| 控件文字 | `13px` 至 `14px` | `500` 至 `650` |
| 辅助说明 | `11px` 至 `12px` | `400` 至 `500` |
| Eyebrow | `10px` 至 `11px` | `700` |

数字设置：

```css
.numeric {
  font-variant-numeric: tabular-nums;
}
```

## 8. 间距、圆角和阴影

### 8.1 间距

统一使用 4px 基础网格：

```text
4 / 8 / 12 / 16 / 20 / 24 / 32 / 40
```

禁止出现无设计依据的 `13px`、`17px`、`23px` 等随机间距。

### 8.2 圆角

| 元素 | 圆角 |
| --- | ---: |
| 浮动侧边栏 | `24px` |
| 主内容 Surface | `16px` |
| 输入框、按钮 | `10px` 至 `12px` |
| 导航项 | `12px` |
| 状态 Tag | `7px` |
| 小图标容器 | `9px` 至 `10px` |

胶囊形状只用于 Badge、计数器和确实需要表达“标签”的元素。

### 8.3 阴影

- 侧边栏可以使用一层柔和冷色阴影。
- Dialog、Popover、Drawer 等浮层可以使用阴影。
- 普通内容 Surface 不使用阴影，以细边框分层。
- 禁止每个 Card 都使用明显阴影。

建议亮色阴影：

```css
box-shadow: 0 20px 60px rgb(48 67 101 / 12%);
```

建议暗色阴影：

```css
box-shadow: 0 24px 70px rgb(7 12 24 / 30%);
```

## 9. 页面 Surface

只定义三类 Surface：

| 类型 | 用途 |
| --- | --- |
| Primary Surface | 页面主要内容 |
| Secondary Surface | 工具栏、摘要、辅助内容 |
| Overlay Surface | Dialog、Drawer、Popover |

规则：

- 不将每一段文字或每个数字做成单独 Card。
- 同一层级的 Surface 保持一致圆角和边框。
- Surface 内部优先通过间距和细分隔线组织内容。
- 主内容应尽可能使用横向空间，不强制限制在 1200px 居中容器。

## 10. 组件规范

### 10.1 Button

- 主要按钮使用宝石蓝背景和月石白文字。
- 每个页面同时只突出一个主要按钮。
- 次要按钮使用透明或 Surface 背景加细边框。
- 香槟金不作为普通主要按钮背景。
- 危险操作使用危险色，并通过确认流程保护。
- 按钮文案直接描述结果，例如“保存修改”“刷新数据”。

### 10.2 Input、Select 和 DatePicker

- 默认背景使用 `surface` 或 `surface-soft`。
- 默认边框使用 `border`。
- 聚焦状态使用 `focus` 色和外部焦点环。
- Placeholder 使用 `text-muted`。
- 标签放在输入框上方。
- 错误提示紧邻字段，不只使用红色边框。

### 10.3 DataTable

- 表头使用 `surface-soft` 或与内容面一致的弱层级。
- 表头文字使用 `text-muted`。
- 表格行高控制在 `44px` 至 `48px`。
- 悬停使用 `surface-hover` 或低透明度 `selection`。
- 操作列固定在右侧。
- 大量数据使用服务端分页或虚拟滚动。
- 表格数字右对齐或保持稳定的等宽排版。
- 表格外层不得重复套用多个 Card。

### 10.4 Tag 和 Badge

- Tag 必须同时包含文字。
- 圆角使用 `7px`，避免全部使用胶囊形状。
- 状态图标和文字颜色保持一致。
- 普通状态不使用香槟金。
- 数量 Badge 可以使用圆形或胶囊形。

### 10.5 Tabs 和 SelectButton

- 用于同一上下文内的视图切换。
- 激活项使用 `surface` 加宝石蓝文字，或宝石蓝背景加月石白文字。
- 不使用高饱和渐变。
- 页签数量过多时应改用二级导航或菜单。

### 10.6 Dialog、Drawer 和 Popover

- Dialog 只用于需要集中注意力的操作。
- 快速查看和轻量编辑优先使用 Drawer。
- Popover 用于短内容，不承载复杂表单。
- 浮层关闭后应恢复触发元素焦点。
- 移动端侧边栏使用 Drawer。

### 10.7 Toast 和 Message

- 成功、警告、错误必须使用明确文案。
- 文案描述发生了什么以及用户下一步能做什么。
- Toast 不用于必须由用户确认的重要信息。
- 相同操作在按钮、Toast 和日志中使用相同动词。

## 11. 导航规范

### 11.1 侧边栏

- 桌面端使用宽度 `248px` 的浮动圆角侧边栏。
- Logo 位于顶部。
- 一级导航位于中部。
- 设置和用户信息固定在底部。
- 当前导航项使用宝石蓝整块背景。
- 当前导航项左侧可以使用 `3px` 的香槟金至宝石蓝渐变线。
- 未激活导航项保持透明背景。
- 图标使用统一线性风格，建议 `18px` 至 `20px`。

### 11.2 二级导航

- 不应无限嵌套在侧边栏。
- 优先使用页面内 Tabs、分段控制或局部导航。
- 当前路径应能通过页面上下文和标题被理解。

## 12. 图表规范

### 12.1 默认色序

```text
主序列       #3F5F9A / 暗色 #7899D1
对比序列     #91A7C6 / 暗色 #AEBED4
关键时点     #E6B84F / 暗色 #F2C96B
网格线       主题 grid Token
文字         主题 text-secondary Token
```

规则：

- 香槟金用于关键时点、选中游标和少量特殊数据点。
- 不使用大面积金色 Area 填充。
- 网格线低透明度，不与数据线竞争。
- Tooltip 遵循当前明暗主题。
- 图例和坐标轴使用统一字号。
- 图表组件必须响应容器尺寸变化。
- 图表配置和数据转换逻辑分离。
- 数据语义色与主题色分开管理。

### 12.2 ECharts 主题

建议创建：

```text
src/components/charts/
├── themes/
│   ├── lucking-light.ts
│   └── lucking-dark.ts
├── BaseChart.vue
└── chart-tokens.ts
```

图表主题不得在各页面重复声明相同颜色。

## 13. 交互和动效

推荐时长：

| 交互 | 时长 |
| --- | ---: |
| Hover 和颜色变化 | `120ms` 至 `150ms` |
| Drawer 和侧边栏 | `180ms` 至 `220ms` |
| Dialog | `160ms` 至 `200ms` |
| 页面轻量过渡 | 不超过 `220ms` |

规则：

- 动效服务于状态变化，不做持续性装饰动画。
- 表格刷新不能导致整页闪烁。
- 数据更新时只强调变化区域。
- 必须支持 `prefers-reduced-motion`。
- 主题切换应平滑，但截图和自动化测试需要等待过渡完成。

## 14. 加载、空状态和错误状态

### 14.1 加载

- 页面首次加载使用 Skeleton。
- 局部刷新保留原数据并显示轻量刷新状态。
- 不因单个组件刷新而遮挡整个页面。
- 按钮提交期间禁用重复提交。

### 14.2 空状态

空状态应说明：

1. 当前为什么没有内容。
2. 用户可以执行什么操作。

禁止只显示“暂无数据”。

### 14.3 错误状态

- 明确说明失败的操作。
- 提供重试或返回入口。
- 显示可供排查的请求标识时，不暴露敏感信息。
- 错误不能只通过 Toast 一闪而过。

## 15. 响应式规范

| 宽度 | 行为 |
| --- | --- |
| `≥ 1120px` | 完整侧边栏与多列内容 |
| `860px - 1119px` | 缩小页面间距，摘要区允许两列 |
| `< 860px` | 侧边栏改为 Drawer，内容改单列 |
| `< 620px` | 搜索折叠，操作区换行，摘要改为单列 |

规则：

- 桌面端优先，但页面不得在窄屏下失去基本操作能力。
- 表格在移动端可以横向滚动，不强制转换为卡片。
- 图表保留合理最小高度。
- 点击目标不小于 `40px × 40px`。

## 16. 可访问性

- 保留 PrimeVue 默认语义和 ARIA 属性。
- 所有图标按钮必须提供可访问名称。
- 所有表单控件必须具有关联标签。
- 所有操作支持键盘完成。
- 焦点状态使用 `focus` Token，不能被移除。
- 状态不能只通过颜色表达。
- 图表提供文本摘要或可访问说明。
- 颜色调整后必须检查亮色和暗色对比度。

## 18. 禁止事项

- 禁止使用纯黑 `#000000` 或纯白 `#FFFFFF` 作为主背景。
- 禁止在主题和通用状态中使用绿色。
- 禁止将香槟金用作大面积背景。
- 禁止页面自行新增品牌主色。
- 禁止在模板中直接写主题十六进制颜色。
- 禁止为每一块内容增加阴影 Card。
- 禁止同时引入第二套 UI 组件库。
- 禁止使用不同风格的线性和填充图标。
- 禁止使用无意义渐变、玻璃拟态和持续动画。
- 禁止移除键盘焦点样式。
- 禁止仅用颜色表示状态。
- 禁止单页重复实现已有的公共 Surface、状态和空状态组件。

## 19. 页面开发流程

新增页面按照以下顺序开发：

1. 明确页面唯一目标和主要操作。
2. 选择页面布局和 Surface 结构。
3. 使用已有 PrimeVue 组件和公共组件。
4. 接入 Design Token，不写局部主题色。
5. 实现加载、空状态、错误和权限状态。
6. 完成亮色和暗色主题检查。
7. 检查键盘操作和焦点状态。
8. 检查 `860px` 和 `620px` 响应式断点。
9. 运行类型检查、单元测试和生产构建。
10. 使用浏览器截图完成视觉复核。
